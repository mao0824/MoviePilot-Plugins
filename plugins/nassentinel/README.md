# NAS 哨兵 (NasSentinel)

一个**通用巡检哨兵**插件：把「站点签到、考核进度、刷流与磁盘 IO 健康」这三件需要人盯的事，变成自动巡检 + 到点告警。

## 特性

- 🔐 **通用 NexusPHP 签到补位**——为 AutoSignIn 未覆盖的站点补位；自动识别「表单式 / 链接式」签到并幂等执行，已签到自动跳过
- 📊 **考核进度追踪**——解析 NexusPHP 标准考核公告，跟踪「上传增量 / 做种积分」等指标，并**按实测速率外推**预计达成时间与风险等级
- 🎯 **考核单点配置**——可按站点分别指定考核页面与各项指标目标值，解决「同一插件里无法单独配置某个站点考核」的问题
- 🩺 **IO / 刷流健康哨兵**——采样系统负载、IO 等待、物理磁盘队列、读写速率与写延迟，并在**上传速率异常**时告警（专门定位「上传被下载随机 IO 掐死」这类隐形故障）
- 🔔 **每日简报 + 异常即报**——复用 MoviePilot 已有通知渠道，可指定单一渠道，异常侧带独立冷却避免刷屏
- ⚙️ **自动降级 / 自动恢复（默认关闭）**——连续超红线时自动下调刷流下载并发；持续正常后按基线逐步升回
- 🧩 **零硬编码**——设备名、下载器名、站点、阈值、路径全部可配置

## 配置项

### ① 通用

| 配置 | 说明 |
|---|---|
| 启用插件 / 启用通知 | 总开关 |
| 每日简报 / 异常即报 | 简报按周期推送；异常侧可单独控制 |
| 每日巡检周期 | cron 选择器，默认 `30 8 * * *` |
| 通知渠道 | 留空=全部渠道；可选 Web / Telegram / 邮件等 |
| 保存后立即运行一次 | 保存配置即后台跑一次完整巡检（不改变开关） |
| 免打扰开始 / 结束 | 如 `23:30` ~ `07:00`，跨零点自动处理；期间只写日志不推送 |
| 请求超时 / 详细日志 | 网络与排障 |

### ② 站点签到

| 配置 | 说明 |
|---|---|
| 启用签到 / 签到结果通知 | 独立开关 |
| 已签到则跳过 | 幂等执行 |
| 失败重试次数 | 0~5，网络抖动重试 |
| 需要签到的站点 | 多选，来自 MoviePilot 站点列表 |
| 签到相对路径 | 默认 `/attendance.php` |
| 独立签到周期 | 留空则并入每日巡检 |
| 自定义 UA / 自定义 Cookie | 留空则用站点自身配置 |
| 附加表单字段 | 每行一个 `k=v`，POST 时并入表单（个别站点需要固定附加参数） |

### ③ 考核进度追踪

| 配置 | 说明 |
|---|---|
| 启用考核追踪 / 有风险立即通知 | 独立开关 |
| 剩余天数告警阈值 | 剩余天数低于此值且未全部通过时告警 |
| 重点关注指标 | 逗号分隔，如 `上传,积分`，留空=全部 |
| 需要追踪考核的站点 | 多选 |
| 考核页面路径 | 逗号分隔，默认 `/rules.php,/` |
| 识别关键词 | 默认 `考核` |
| 独立考核检查周期 | 留空则并入每日巡检 |
| **考核单点配置** | 按站点覆盖，见下 |

**考核单点配置格式**（每行一条，`#` 开头为注释）：

```
站点ID | 考核页面 | 上传目标 | 做种积分目标 | 分享率目标 | 备注
4 | /rules.php | 83.2GB | 1200 | 1.05 | PTS 新手考核
3 | /rules.php,/ | 上传=300GB | | 分享率=1.2 | 馒头
```

- 目标字段支持**位置式**（第 3/4/5 个字段依次对应 上传 / 做种积分 / 分享率）或**关键词式**（`上传=83.2GB`、`积分=1200`）
- 留空的字段表示沿用页面上的要求；填了就**替代**页面要求参与达成度与风险推算
- 若页面没有提供某个已配置的指标，会明确提示「该站点页面未提供此指标当前值」

### ④ 磁盘 / 刷流 IO 哨兵

| 配置 | 说明 |
|---|---|
| 启用 IO 巡检 | 总开关（在通用分组） |
| 采样间隔 / 采样窗口 | 默认 5 分钟一次、采样窗口 3 秒 |
| 保留最近采样条数 | 页面展示 IO 历史趋势 |
| 告警冷却 | 异常推送独立冷却，默认 30 分钟 |
| 监控设备 | 逗号分隔，留空=自动识别物理盘 |
| 检查刷流下载器速率 / 下载器名 | 留空自动取第一个 qBittorrent |
| 负载红线 / 磁盘队列红线 / IO 等待红线 / 上传速率下限 | 判据 |
| 写延迟参考红线 | 默认 1500ms，`0`=不检查 |

> 写延迟在写缓存 flush 突发时会飙到上千毫秒而队列仍很小，属正常现象，因此默认阈值放得很宽；**判据以「磁盘队列 + 负载」为主**。

### ⑤ 自动降级 / 自动恢复（默认关闭）

| 配置 | 说明 |
|---|---|
| 超红线自动降下载并发 | 主开关，默认关 |
| 每次降低档数 / 并发最低下限 / 降级冷却 | 降级策略 |
| 恢复后自动升回并发 | 默认关 |
| 每次升高档数 / 连续正常多久才升回 | 恢复策略 |

> 首次降级时会记录当时的并发作为**基线**，自动恢复只会升回该基线，不会超过。

## 说明

- 签到与考核解析使用 **Cookie**（读取 MoviePilot 中已配置的站点凭据），插件本身不额外存储明文
- IO 采样读取 `/proc/loadavg`、`/proc/stat` 与 `/proc/diskstats`，需容器可见宿主机 `/proc`（默认即可）
- 日志中未识别签到方式时会输出探测结果，便于人工确认站点机制
- 页面提供「立即巡检 / 立即签到 / 考核检查 / IO 检查」四个手动按钮，长任务后台执行不阻塞页面
