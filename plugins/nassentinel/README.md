# NAS 哨兵 (NasSentinel)

一个**刷流与磁盘 IO 健康哨兵**插件：把「磁盘/刷流 IO 健康、促销敞口」这些需要人盯的事，变成自动巡检 + 到点告警。

> **范围变更（2026-10-10，用户决定）**：站点签到**交给 AutoSignIn**（实测其通用兜底分支可完成 PTS 的链接式签到，并能自校验「已确认站点返回的签到状态」，本机 2026-10-10 00:16 实测通过）；新手考核**交给专门的考核插件**。
> 本插件不再重复实现这两件事——相关代码（签到/考核模块、`/signin` 与 `/exam` 端点、对应按钮与卡片、站点列表依赖）已于 v0.4.0 全部移除，只保留下列功能。

## 特性

- 🩺 **IO / 刷流健康哨兵**——采样系统负载、IO 等待、物理磁盘队列、读写速率与写延迟，并在**上传速率异常**时告警（专门定位「上传被下载随机 IO 掐死」这类隐形故障）
- 📈 **IO 观测与趋势**——历史采样同时记录**上传/下载速率、IO 等待、磁盘队列与「未完成积压量」**，留存默认 288 次（≈24 小时 @5 分钟），并自动压出一行趋势（上传均值/最大、下载均值/最大、队列峰值、积压变化）。**换参数后用这行对比即可判断「哪个组合最有利于拿上传量」**
- ⏳ **刷流促销守护**——读刷流插件逐种子记录的促销截止时间，每天报出「免费期已过却还没下完」和「即将过期却还没下完」的种子（站点的「免费」是限时的，排队久了会在免费期结束后才开跑，那部分下载量会被计费）
- 🔔 **每日简报 + 异常即报**——复用 MoviePilot 已有通知渠道，可指定单一渠道，异常侧带独立冷却避免刷屏
- ⚙️ **自动降级 / 自动恢复（默认关闭）**——连续超红线时自动下调刷流下载并发；持续正常后按基线逐步升回
- 🧩 **零硬编码**——设备名、下载器名、阈值、路径全部可配置

## 配置项

### ① 通用

| 配置 | 说明 |
|---|---|
| 启用插件 / 启用通知 | 总开关 |
| 每日简报 / 异常即报 | 简报按周期推送；异常侧可单独控制 |
| 每日巡检周期 | cron 选择器，默认 `30 8 * * *` |
| 通知渠道 | 留空=全部渠道；可选 Web / Telegram / 邮件等 |
| 保存后立即运行一次 | 保存配置即后台跑一次完整巡检（不改变开关） |
| 免打扰开始 / 结束 | 如 `23:30` ~ `07:00`，跨零点自动处理；期间只写日志不推送 |
| 详细日志 | 排障用 |

### ② 磁盘 / 刷流 IO 哨兵

| 配置 | 说明 |
|---|---|
| 启用 IO 巡检 | 主开关，默认开 |
| 采样间隔 / 采样窗口 | 默认 5 分钟一次、采样窗口 3 秒 |
| 保留最近采样条数 | 建议 **288**（≈24h @5min，默认即此值）；历史每条含上传/下载速率、负载、队列、IO 等待与**未完成积压量** |
| 告警冷却 | 异常推送独立冷却，默认 30 分钟 |
| 监控设备 | 逗号分隔，留空=自动识别物理盘 |
| 检查刷流下载器速率 / 下载器名 | 留空自动取第一个 qBittorrent |
| **磁盘队列红线 / 上传速率下限**（告警判据） | 默认 50 与 1.0 MB/s |
| 负载红线 / IO 等待红线（**仅记录**） | 负载默认 8、IO 等待默认 0=不告警；可用「负载也参与告警」开关让负载重新参与 |
| 写延迟参考红线 | 默认 1500ms，`0`=不检查 |

> **告警判据为什么只留队列 + 上传下限**：这台机器的负载包含 IO 等待，实测常态就在 7.4~9.8，用负载当判据会持续误报；而磁盘队列突发到 100+ 时上传会瞬间掉到 0 附近——那才是「上传被下载随机 IO 掐死」的真信号。负载与 IO 等待仍会照常记录在结果与历史里。
>
> 写延迟在写缓存 flush 突发时会飙到上千毫秒而队列仍很小，属正常现象，因此默认阈值放得很宽。

### ③ 自动降级 / 自动恢复（默认关闭）

| 配置 | 说明 |
|---|---|
| 超红线自动降下载并发 | 主开关，默认关 |
| 每次降低档数 / 并发最低下限 / 降级冷却 | 降级策略 |
| 恢复后自动升回并发 | 默认关 |
| 每次升高档数 / 连续正常多久才升回 | 恢复策略 |

> 首次降级时会记录当时的并发作为**基线**，自动恢复只会升回该基线，不会超过。

### ④ 刷流促销守护

| 配置 | 说明 |
|---|---|
| 启用促销敞口检查 | 主开关，默认开 |
| 提前预警小时数 | 距免费期结束不足该小时数且未下完 → 计入「即将到期」，默认 6 |

> 敞口告警跟随每日巡检节奏（每天最多一条），没有单独的冷却项。

**它解决什么问题**：站点的「免费」是**限时**的（实测有 6h / 12h / 24h 档），而刷流插件抓种时只判断「此刻是否免费」，
**不看还剩多久**。两个刷流任务共用一个下载器时，任务级「同时下载数」之和常超过下载器实际放行数 → 种子排队数小时，
等它真正开跑时免费期可能已经结束，**那部分下载量会被站点计入并扣分享率**。

**判据**：种子记录里的 `freedate`（促销截止）已过 / 即将过，且 `downloaded < size`（未下完）。
其中「仍在下载组」（含排队）的即为**正在产生下载量**的敞口，会单独发一条告警。

**数据来源**：只读刷流插件（BrushFlow）逐种子记录在 MoviePilot 自身数据库 `plugindata` 表里的 `freedate` 字段，
不调用刷流插件的任何私有方法；读不到时降级为「无数据」，不影响其它模块。

> **根治手段在刷流插件那一侧**：把刷流任务的「促销过期即删未下完的种子」打开，
> 到期时刻会自动删除尚未下完的种子（未开跑的种子 0 下载量、0 计费）。本模块只负责**发现与告警**，不会改动任何种子。

## 界面

- **配置页**：四个分组各一张卡片（① 通用 / ② 磁盘·刷流 IO 哨兵 / ③ 自动降级·自动恢复 / ④ 刷流促销守护）；未被启用的模块会自动收起其细节参数（条件显隐）
- **数据页**：卡片布局的结果面板（IO 健康 / 刷流促销敞口 / IO 历史采样）+ 两排共 6 个操作按钮
  - **启用插件 / 禁用插件**——走 MoviePilot 的插件配置用例（保存配置 + 重新初始化 + 刷新调度），与插件列表里的开关等效
  - **立即巡检**（IO + 促销敞口）、**测试通知**（忽略免打扰时段）、**IO 检查**、**促销敞口**

> 说明：配置表单渲染器不绑定点击事件，所以操作按钮统一放在「数据」页；配置页顶部会提示这一点。

## 对外端点

`/run`、`/io`、`/promo`、`/enable`、`/disable`、`/test_notify`（全部 `auth: bear`，GET/POST 均可）。

## 说明

- IO 采样读取 `/proc/loadavg`、`/proc/stat` 与 `/proc/diskstats`，需容器可见宿主机 `/proc`（默认即可）
- 长任务后台执行，不阻塞页面（按钮点完约 10~20 秒刷新本页可见结果）
- 每日巡检的异常推送在**手动触发时不会发通知**（避免调试刷屏），只写日志与落盘；「测试通知」按钮例外
